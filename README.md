# 取り付け工程表

現場ごとの取り付けの予定（サッシや玄関ドアの搬入・取り付け・検査など）を、現場名・施工業者と並べてカレンダー上の棒で管理し、文字が重ならないように印刷するためのツールです。今まで Excel で作っていた取付工程表を、画面で入力できるようにしたものです。

- **ブラウザ版**：HTML ファイル 1 つで動きます（インストール不要・インターネット接続不要）
- **デスクトップ版（Mac・Windows）**：ブラウザ版と同じ画面に、ChatGPT のアカウントでログインした AI（Codex）に頼めるパネルが付いています。今までの Excel の工程表を添付して、移してもらうこともできます
- **MCP サーバー**：Claude のデスクトップアプリなどの AI エージェントから、保存データを読み書きできます

## ダウンロード

[リリースのページ](https://github.com/iori0311/koutei/releases/latest)から、使うものをダウンロードします。

| ファイル | 中身 |
| --- | --- |
| `koutei-<版>-mac-apple-silicon.dmg` | Mac のアプリ（M1 以降のチップ） |
| `koutei-<版>-mac-intel.dmg` | Mac のアプリ（Intel のチップ） |
| `koutei-<版>-windows-x64-setup.exe` | Windows 10・11 のアプリ（インストーラー） |

Mac のチップは、アップルメニュー →「この Mac について」の「チップ」で確かめられます。

ブラウザ版と MCP サーバーは配っていません。使うときは、このリポジトリから作ります（下の「開発」の「ブラウザ版・MCP サーバー」）。

### デスクトップ版をはじめて開くとき

このアプリには、Apple・Microsoft の開発者の署名がまだ付いていません。そのため、はじめて開くときだけ警告が出ます。

**Mac**

1. dmg を開いて、「取り付け工程表」を「アプリケーション」に入れる
2. アプリケーションから開く。「開いていません」と出たら「完了」を押す
3. 「システム設定」→「プライバシーとセキュリティ」を開き、下のほうの「このまま開く」を押す（パスワードを聞かれたら入れる）。もう一度「開く」を押す

**Windows**

1. `setup.exe` を開く。「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」を押す
2. 管理者の権限なしで、自分のユーザーにだけ入ります。スタートメニューの「取り付け工程表」から開きます


## 使い方

1. デスクトップ版はアプリを開く。ブラウザ版は `取り付け工程表.html` を Chrome か Edge で開く（ダブルクリック）
2. 「すべての現場」のタブで、一覧の一番下の「＋ 現場を追加」を押し、現場名と施工業者を入れる
   - 施工業者が何社かあるときは、今までの取付工程表と同じように 1 行に 1 社ずつ改行して書きます（改行のしかたは下の 3. と同じ）。ビューで施工業者を絞り込むとき、1 社ずつ選べます
   - 施工業者は、一度入れたものが候補として自動でたまります。欄を押すと候補が並び、打った文字で絞り込めます（ひらがなで打ってもカタカナの名前に当たります）。打ち間違えた候補は、乗せると出る × で外せます
3. 現場名・施工業者を直すときは、その行の現場名・施工業者のところを押す（ひとかたまりなので、どこを押しても同じ） … すぐ下に小さなパネルが出て、その場で直せます（現場の削除もここ）。パネルの外を押すと閉じます（同じところをもう一度押しても閉じます）
   - 現場名・施工業者は、`Shift+Enter`（Excel のセルと同じ `Alt+Enter` でも）で好きな位置で改行できます。改行は一覧にも印刷にもそのまま出ます
4. その現場の行の、日付の下をクリックすると予定ができる（カーソルを乗せた日に「＋」の枠が出ます）。その行のすぐ下に小さなパネルが出るので、種別（色）・内容・開始日・終了日を入れる（パネルが開いてもカレンダーの幅は変わりません。パネルの外を押すと閉じます。空いている日を押して閉じたときは、予定はできません）
   - 内容は、打っている途中からガントに出ます。棒に入るときは棒の中、入らないときは棒の横に出し、ほかの棒や文字と重ならないように段を分けて並べます（印刷も同じ並べ方）
   - 棒をクリック … その予定を直す・削除する
   - 棒の真ん中をつかんで動かす … 日程を移動。棒の両端の取っ手をつかむ … 期間を伸ばす・縮める（動かしている間は行き先の日付が光ります）。取っ手は棒の端の少し外側までつかめるので、1 日だけの細い棒でも伸ばせます
   - 棒に乗せると左上に出るピンを押す … その予定を固定（ピンが刺さった棒は動かせず、つかもうとすると震えます）。もう一度押すと外れます
5. 何月〜何月を出すかは、上の月の帯で選ぶ（1〜12 か月）。選んだ期間は画面の横幅にちょうど収まります。ただし日付と曜日が読める幅より細くはしないので、入りきらない長い期間は横スクロールで見ます（1440px 幅の画面ならおよそ 2 か月、1920px 幅ならおよそ 3 か月までがスクロールなしで入ります）。印刷は期間の長さにかかわらず用紙にちょうど収まります
   - 青い帯が今出している期間です。真ん中をつかんで動かす … 期間をずらす／両端の取っ手をつかむ … 伸ばす・縮める／帯の外の月を押す … その月からに移る（押したまま横になぞると、その範囲を選び直せます）／◀ ▶ … 1 か月ずつずらす
6. ビュー（上のタブ）… 出す現場と期間をまとめて覚えておけます
   - 「すべての現場」はいつもあります。＋ で新しいビューを作り、名前を付けて、出す現場を絞り込みます（＋ は現場が 1 つ以上あるときに出ます）
   - 絞り込みは Excel のフィルターと同じ考え方です。「現場」と「施工業者」の一覧が並んでいて、両方でチェックが入っている現場だけが出ます（はじめは全部にチェック）。一番上の「すべて」で全部の付け外し。もう一方の一覧で外れていて出ないものは薄くなり、施工業者の横の数は、今の現場のチェックで残る現場の数です
   - 「すべて」にチェックが入っている一覧は、あとで足した現場・施工業者も自動で出ます（例：施工業者だけを絞り込んだビューには、その施工業者の新しい現場も出ます）
   - 開いているタブをもう一度押すと、名前・出す現場を変えたり、ビューを削除したりできます（現場そのものは消えません）
   - 現場を追加するのは「すべての現場」だけです。ビューでは、作ってある現場から出すものを選びます（まだ出していない現場があるときは、一覧の一番下に「出す現場を選ぶ」が出ます）
   - 期間はビューごとに覚えます
7. 右上の「印刷」で、開いているビューをそのまま印刷（出す現場・期間はビューのまま。用紙 A4/A3/B4・縦横を選ぶ）。印刷プレビューの月の帯で期間を変えると、そのビューの期間も変わります。PDF にしたいときは印刷画面の送信先で「PDF に保存」

種別（色）は、今までの取付工程表の凡例と同じ 9 種類（「工事日決定」「サッシ搬入」「玄関ドア搬入」「検査・引渡し・社内検査」「補修工事」「自主検査」「災防協」「手直し」「応援」）と、色を付けない「色なし」で始まります。種別は画面上の凡例でそのまま変えられます（色の四角 … 色を変える／名前 … 名前を変える／乗せると出る × … 削除（その種別の予定は「色なし」になります）／右端の ＋ … 追加）。日曜・祝日（振替休日・国民の休日を含む）はうすいオレンジ、土曜はうすい灰色で自動で網掛けされます。

`Ctrl+Z` で元に戻す、`Ctrl+Shift+Z`（または `Ctrl+Y`）でやり直す、`Esc` でパネルを閉じます（Mac では `Ctrl` の代わりに `⌘` でも）。

## データの保存について

- 入力した内容はこのパソコンのブラウザの中に自動保存されます（外部には送信しません）
- 別のパソコンで使う・控えを残すときは「保存」でデータファイル（`.json`）に書き出し、「データ」→「開く」で読み込みます
- Chrome・Edge では、「保存」で書き出したファイルや「開く」で開いたファイルと画面がつながります。つながっている間は：
  - 画面で変えた内容が、そのファイルにも自動で保存されます（右上に「『工程データ_….json』に自動保存」と出ます）
  - そのファイルがほか（AI エージェントなど）で書き換えられると、2 秒ほどで画面に読み込みます。読み込んだ変更は「元に戻す」（`Ctrl+Z`）で取り消せ、取り消した内容はファイルにも戻ります
  - 画面と外の両方で同じ予定を同時に変えていたときは、画面の内容を残します
  - 次にこの HTML を開いたときも、同じファイルにつなぎ直します。ブラウザが許可を求めるときは、右上の「『…』とつなぎ直す」を押してください
  - つながりをやめるときは「データ」→「ファイルとのつながりを外す」（ファイルはそのまま残ります）
- 何もない状態から始め直すときは「データ」→「最初の状態に戻す」（つながっていたファイルは、控えとしてそのまま残ります）

## デスクトップ版（AI に頼める）

ブラウザ版と同じ画面に、右上の「AI」で開くパネルが付いたアプリです（Mac・Windows）。ChatGPT のアカウントでログインした Codex に、ふだんの言葉で頼めます（例：「来週の予定を一覧にして」「（現場名）に 11/20 の玄関ドア搬入を入れて」）。

1. アプリを開く（はじめて開くときは、上の「デスクトップ版をはじめて開くとき」）
2. 右上の「AI」→「ChatGPT でログイン」。ブラウザでログインすると、パネルが自動で切り替わります（ログインは次からも残ります。パネルの「ログアウト」で消せます）
3. 頼みたいことを書いて、↑ のボタン（または `Enter`）で送る。改行は `Shift+Enter`。回答を作っている間は同じボタンが ■ になり、押すと止まります

- AI が変えたものは、すぐ画面に出ます。パネルの「この回答の変更 〇 件を元に戻す」でまとめて、または「元に戻す」（`Ctrl+Z`）で 1 つずつ取り消せます
- AI ができるのは、下の MCP と同じ操作（現場と予定を見る・足す・直す・消す）と、添付したファイルを読むことだけです。ピンで固定した予定は動かせず、消せません。種別（凡例）とビューは変えられません。消す前には AI が確かめます
- パネルの クリップ のボタン（またはパネルにファイルを落とす）で、Excel（.xlsx）・CSV・画像を添付できます。今まで Excel で管理していた工程表を添付して「移して」と頼むと、AI が中身を読み、移す内容（現場と予定の数・期間・終わった現場を入れるか・凡例の色と種別の対応）を確かめてから移します。移したものは「この回答の変更 〇 件を元に戻す」でまとめて取り消せます
  - Excel はこのアプリの中で読みます。「現場名」「施工業者」の列と、日の列に色を塗った予定・凡例を見つけて、現場ごとの予定に読み解きます。年が書いていなくても、月の見出し・1 日の曜日・月の日数から決めます。土日・祝日・定休日の網掛けは予定に数えません。色の近くに書いた文字は、その予定の内容にします
  - 凡例が途中で変わっているときは、いちばん多く使われている名前にします。凡例にない色・合う種別がない色は、どうするか AI が聞きます
  - 古い形式の .xls は、Excel で .xlsx として保存し直してから添付します
  - 添付の中身は、頼みを送ったときに ChatGPT（Codex）へ送られます
- Codex はアプリに入っています（`codex-cli 0.153.4`。[openai/codex](https://github.com/openai/codex) のリリースの実行ファイルをそのまま同梱し、起動するたびに版と中身を確かめます）。シェル・ファイルの編集・Web 検索は切ってあり、読むだけのサンドボックスで動きます。ログイン情報はこのアプリ専用の場所に置き、いつもの Codex（`~/.codex`）とは分けています
- 保存・開く・印刷はアプリの画面で行います。保存・開いたファイルとつながる仕組み（自動保存・外の変更の読み込み）はブラウザ版と同じなので、下の MCP サーバーと一緒にも使えます
- データはアプリの中に自動保存され、ブラウザ版とは別です。ブラウザ版のデータを使うときは、ブラウザ版で「保存」したファイルをアプリの「データ」→「開く」で開きます

## AI エージェントから操作する（MCP）

Claude のデスクトップアプリや自前のエージェントから、現場・予定を読み書きできます。エージェントには HTML（アプリ本体）を渡さず、保存データ（`.json`）だけを、決まった操作で読み書きさせます。

1. `取り付け工程表_mcp.mjs`（作り方は下の「開発」）を好きな場所に置く。画面（ブラウザ版・デスクトップ版のどちらでも）の「保存」で、保存データ（例：`工程データ.json`）を作る。画面はこのファイルとつながり、エージェントの変更がすぐ画面に出ます
2. Claude のデスクトップアプリの設定ファイル（macOS は `~/Library/Application Support/Claude/claude_desktop_config.json`、Windows は `%APPDATA%\Claude\claude_desktop_config.json`）に次を足して、アプリを起動し直す。パスは 2 つともフルパスで書きます

   ```json
   {
     "mcpServers": {
       "torituke-koutei": {
         "command": "node",
         "args": ["/フルパス/取り付け工程表_mcp.mjs", "/フルパス/工程データ.json"]
       }
     }
   }
   ```

   - Node.js 18 以上が必要です。`node` が見つからないと言われたら、`command` に node のフルパスを書きます（macOS ならターミナルで `which node` と打つと出ます）
   - 自前のエージェントからは、同じコマンド（`node 取り付け工程表_mcp.mjs 工程データ.json`）を、標準入出力でやりとりする MCP サーバーとして起動します

エージェントができること：

| ツール | できること |
| --- | --- |
| `list_sites` | 現場の一覧（id・現場名・施工業者・予定の数・最初と最後の予定日）。文字で絞り込める |
| `list_events` | 予定の一覧（現場・期間・種別で絞り込める） |
| `list_categories` | 種別（凡例）の一覧 |
| `add_site` / `update_site` / `delete_site` | 現場の追加・現場名と施工業者の変更・削除（その現場の予定も消える） |
| `add_event` / `add_events` / `update_event` / `delete_event` | 予定の追加（`add_events` は 1 つの現場にまとめて 100 件まで。1 件でもおかしければ何も足さない）・日付と種別と内容の変更・削除 |

決まり（エージェントには守らせるのではなく、MCP サーバーの側でできないようにしてあります）：

- 保存データの項目は増やせません。決まっていない項目を渡すと断ります（「担当」「状態」など）
- ピンで固定した予定は、日付の変更も削除もできません。ピンの予定がある現場も削除できません（ピンは画面で付け外しします）
- 種別（凡例）とビューは読むだけです（変えるのは画面で）
- 日付は `YYYY-MM-DD`（2000〜2099 年）、施工業者は 1 行に 1 社。現場名が同じ現場は作りません
- 書き換えるたびに、書き換える前の中身を保存データの隣の「`工程データ_控え`」フォルダに残します（新しいものから 30 個）
- HTML とソース（`src/`）には触りません。エージェントにこのフォルダの書き込みを許すときは、HTML と `src/` を書き換えないよう設定しておくと安心です

## 開発

### ブラウザ版・MCP サーバー

ソースは `src/` にあります。Node.js 18 以上だけで作れます（追加のパッケージは要りません）。サンプルの中身は `src/sample-data.json` です。

```bash
node build.mjs   # 取り付け工程表.html・取り付け工程表_サンプル.html・取り付け工程表_mcp.mjs・desktop/dist を作る
npm test         # 作り直して、テスト（tests/）を通す
```

できるファイル：

| ファイル | 中身 |
| --- | --- |
| `取り付け工程表.html` | ブラウザ版の本番用。何も入っていない状態で開きます |
| `取り付け工程表_サンプル.html` | 見本の現場 2 件が入った状態で開きます。ここでの変更は本番用とは別に保存されます。「データ」→「サンプルを最初の状態に戻す」で元どおりにできます |
| `取り付け工程表_mcp.mjs` | AI エージェントから操作するための MCP サーバー（上の「AI エージェントから操作する」） |

### デスクトップ版

[Tauri 2](https://tauri.app/) のアプリです。Rust と Node.js が要ります（Windows では、Tauri の[事前の準備](https://tauri.app/start/prerequisites/)も）。

```bash
cd desktop
npm ci
npm run fetch:codex   # 同梱する Codex を取ってくる（版とハッシュは src-tauri/codex.json に固定）
npm run dev           # 開発用に起動する
npm run app           # インストーラーを作る（src-tauri/target/release/bundle/）
```

- `npm run check:codex` … 同梱の Codex をアプリと同じ設定で起動し、偽のモデル（127.0.0.1）を相手に、道具の呼び出しから回答までを確かめます（ログイン・外への通信なし）
- `node scripts/fake-model.mjs 8799` を動かしたまま `KOUTEI_CODEX_PROBE=http://127.0.0.1:8799/v1` を付けて `cargo test`（`src-tauri` で）や `npm run dev` をすると、ログインなしで AI のパネルまで確かめられます（開発用のビルドだけ）
- Codex の版を上げるときは、`src-tauri/codex.json` の版・ハッシュを書き換え、上の 2 つで確かめます

### ファイルの役割

| --- | --- |
| `src/gantt-web.js` | 画面（全体工程・凡例での種別の編集・棒のドラッグとピン・棒のそばに出る予定を直すパネル） |

| `src/print.js` | 印刷プレビューと印刷レイアウト |

| `src/agent-ops.js` | エージェント用の操作（入力の確かめ・ピンを守る。MCP サーバーで使う） |

### リリースの出し方

1. `desktop/src-tauri/Cargo.toml` の `version` を上げて、`main` に push する（CI が通るのを待つ）
2. 同じ版のタグを push する

   ```bash
   git tag v0.1.1
   git push origin v0.1.1
   ```

3. GitHub Actions が Mac（Apple シリコン・Intel）・Windows のインストーラーを作り（Mac は、下の「署名の設定」がしてあれば署名と公証まで）、[リリース](https://github.com/iori0311/koutei/releases)の下書きに載せます。中身を確かめて「Publish release」を押すと公開されます

### 署名の設定（Mac）

Apple の Developer ID で署名して公証すると、Mac ではじめて開くときの「このまま開く」が要らなくなります。リポジトリの secrets に次の 5 つを登録すると、リリースのワークフローが署名と公証をします（登録がなければ、今までどおり ad-hoc 署名で作ります）。

| secrets | 中身 |
| --- | --- |
| `APPLE_CERTIFICATE` | 「Developer ID Application」の証明書（秘密鍵ごと書き出した `.p12`）を base64 にしたもの |
| `APPLE_CERTIFICATE_PASSWORD` | `.p12` を書き出したときに付けたパスワード |
| `APPLE_API_KEY_P8` | 公証に使う App Store Connect の API キー（`.p8` ファイルの中身） |
| `APPLE_API_KEY` | その API キーの Key ID |
| `APPLE_API_ISSUER` | Issuer ID |

1. [Apple Developer Program](https://developer.apple.com/programs/enroll/) に登録する。証明書には登録した名前（個人で登録したなら本人の名前）が入り、署名したアプリから誰でも読めます
2. 証明書を作る
   - 「キーチェーンアクセス」のメニュー →「証明書アシスタント」→「認証局に証明書を要求」で、「ディスクに保存」を選んで要求ファイル（`.certSigningRequest`）を作る
   - [Certificates](https://developer.apple.com/account/resources/certificates/list) の ＋ で「Developer ID Application」を選び、要求ファイルを上げる。できた `.cer` をダウンロードして、ダブルクリックでキーチェーンに入れる
   - キーチェーンアクセスの「自分の証明書」で「Developer ID Application: …」を右クリック →「書き出す」で `.p12` にする（パスワードを付ける）
3. 公証用の API キーを作る：[App Store Connect](https://appstoreconnect.apple.com/) の「ユーザとアクセス」→「統合」→「App Store Connect API」で、チームキーを ＋（アクセスは「Developer」）。`.p8` をダウンロードし（1 回しかできません）、Key ID と Issuer ID を控える
4. secrets に登録する。値は画面に出さずに、そのまま GitHub に送ります（パスワード・Key ID・Issuer ID は、聞かれたら貼る）

   ```bash
   base64 -i 書き出した.p12 | gh secret set APPLE_CERTIFICATE --repo iori0311/koutei
   gh secret set APPLE_CERTIFICATE_PASSWORD --repo iori0311/koutei
   gh secret set APPLE_API_KEY_P8 --repo iori0311/koutei < AuthKey_XXXXXXXXXX.p8
   gh secret set APPLE_API_KEY --repo iori0311/koutei
   gh secret set APPLE_API_ISSUER --repo iori0311/koutei
   ```

   登録したら、`.p12` と `.p8` のファイルは消してかまいません（秘密鍵はキーチェーンに残ります。API キーは作り直せます）
5. 「Actions」→「リリース」→「Run workflow」で、タグを付けずに試せます（下書きは作りません）。Mac の「確かめる」に「Developer ID で署名し、公証済み」と出れば通っています
